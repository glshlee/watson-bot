# ADR-029: 2단계 사전 검토 및 원터치 승인 워크플로우 (Two-Phase Draft Review & Confirmation Workflow)

## 1. Context (배경 및 문제점)
사용자 피드백: *"이왕이면 기록전에 검토를 받는건 엌대?"* -> *"응"*

1. **원치 않는 내용의 즉시 영구 기록 및 Git 오염 우려**:
   - 기존 방식은 사용자가 대화 도중 운동, 업무, 일상 사연을 이야기했을 때, 의도 분석에 따라 곧바로 파일에 마크다운을 추가하고 Git에 커밋·푸시하거나, 혹은 일반 잡담으로 처리되는 양극단이 존재했다.
   - 사용자는 자신의 소중한 일기/GTD 파일에 어떤 문장으로 다듬어져 어떤 경로(`logs/daily/YYYY-MM-DD.md`, `gtd/inbox.md`)에 저장될지 사전에 시각적으로 확인하고 수정하거나 승인하고 싶은 자연스러운 니즈가 있었다.
2. **사전 검토(Draft Preview) 표현과 인터랙션의 부재**:
   - 비서가 기록을 제안(`log_suggest`)할 때 어떤 서식으로 들어갈지 명확한 미리보기 카드(타임스탬프, 대상 파일, 정제된 본문)가 부족했고, 버튼이나 원터치 확인 수단이 부재하여 번거롭게 타이핑해야 했다.
3. **복합 일상(서사 + 액션 태스크)에 대한 동시 검토 필요**:
   - 가족 간호, 병원 검진, 여행 등 사연 속에 실천 과제가 포함된 경우, 일일 로그 초안과 GTD 인박스 초안을 동시에 보여주고 한 번에 승인받는 지능형 2단계 커밋 구조가 요구되었다.

## 2. Decision (결정 사항)

### 2.1 2단계 사전 검토 초안 카드 (Draft Preview Card) 제공
- 사용자가 운동, 아이디어, 업무 성과, 가족/식사/병원 등 삶의 일과를 이야기하면 즉시 마크다운 파일을 수정하지 않고 `log_suggest` 인텐트로 전환.
- 왓슨 비서는 다정하고 공감 어린 멘트와 함께 명확한 **마크다운 초안 카드**를 제시:
  ```markdown
  ### 📝 라이프로그 초안 (`logs/daily/YYYY-MM-DD.md` [Category])
  - [HH:MM] 사용자 일상 서사

  ### 📥 GTD 수집함 초안 (`gtd/inbox.md`) (실천 과제 감지 시)
  - [ ] 추출된 핵심 액션 태스크
  ```
- 세션 메타데이터(`pending_log`)에 `content`, `category`, `gtd_task`, `is_dual` 상태를 SQLite에 영속화.

### 2.2 텔레그램 & 웹 대시보드 원터치 인라인 액션 버튼 연동
- **텔레그램**: `log_suggest` 발생 시 메시지 하단에 인라인 키보드 부착:
  - `[✅ 응, 기록해줘]` (`callback_data: confirm_log`)
  - `[❌ 아니야]` (`callback_data: reject_log`)
  - 0.1초 고속 콜백 응답과 함께 원클릭으로 백엔드 물리 기록 및 Git 커밋·푸시 완결.
- **웹 콘솔 (`/watson`)**: 제안 카드 수신 시 퀵 액션 버튼 동적 렌더링:
  - `[응, 기록해줘]` (클릭 시 "응 좋아" 발송 후 즉시 확정)
  - `[아니야]` (클릭 시 "아니 괜찮아" 발송 후 제안 취소)

### 2.3 결정론적 승인/거절 분기 및 맥락 보존
- 사용자가 버튼 클릭 또는 자연어로 승인("응", "좋아", "이대로 해줘", "이대로 기록해줘", "부탁해" 등) 발화 시:
  - `gtd_task` 유무에 따라 `log_confirm`(단일 일일 로그) 또는 `log_dual`(일일 로그 + GTD 인박스 동시 기록)을 실행하고 원자적 1커밋 1푸시 집행.
  - 완료 후 `pending_log`를 안전하게 비움.
- 사용자가 거절("아니야", "괜찮아", "기록하지 마" 등) 발화 시:
  - `log_reject`로 전환되어 파일을 건드리지 않고 편안한 대화로만 기억하며 `pending_log`를 초기화.
- 사용자가 맥락을 직접 지정하거나 추가 서사를 덧붙이는 경우("오늘 로그에 내가 아까 말한 내용도 기록해줘. 내 감정이니까"):
  - 단순 확인(`confirm_patterns`)으로 오인하지 않고 맥락 역추적(`log_explicit`)으로 안전하게 우회하여 누락 없이 반영.

### 2.4 파워유저용 패스트트랙 (`/log` 직접 기록) 유지
- 사전 검토를 거치지 않고 곧바로 디스크 기록 및 Git 커밋을 원하는 사용자를 위해 `/log [내용]` 커맨드는 2단계 검토를 우회하여 0초 만에 즉시 물리적 기록 및 푸시 집행.

## 3. Consequences (영향 및 효과)
- **기록 통제권과 심리적 안정감 극대화**: 사용자가 파일에 쓰이기 전에 정확한 마크다운 형태와 대상 파일을 눈으로 직접 확인하고 승인하므로, 잘못된 내용이 Git에 영구 커밋되는 사고를 원천 방지.
- **모바일/웹 원터치 편의성**: 키보드로 긴 문장을 칠 필요 없이 텔레그램 인라인 버튼이나 웹 퀵 칩을 '톡' 누르는 것만으로 완벽한 라이프로그 + GTD 동기화 완성.
- **패스트트랙과 지능형 비서의 조화**: 바쁠 때는 `/log`로 바로 기록하고, 여유롭게 일상을 이야기할 때는 친절한 검토와 다정한 공감을 받는 프리미엄 비서 경험 제공.
