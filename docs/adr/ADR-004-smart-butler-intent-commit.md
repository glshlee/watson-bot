# ADR-004: 지능형 라이프로그 비서(Watson Butler) 의도 분리 및 확정 시 1기록 1커밋 아키텍처

* **상태 (Status)**: 승인됨 (Accepted)
* **날짜 (Date)**: 2026-09-04
* **작성자 (Author)**: Watson Core Team & User

---

## 1. 맥락 (Context)
기존 시스템(`ADR-003`)에서는 웹 대시보드 및 API를 통해 메시지가 입력될 때마다, 단순 인사나 잡담, 일반 질문까지 모든 대화 1건당 1개의 마크다운 라이프로그 추가 및 Git 커밋이 기계적으로 즉시 발생하였다.
이로 인해:
1. 불필요한 단순 대화가 라이프로그 마크다운에 오염됨.
2. Git 커밋 히스토리가 사소한 잡담으로 과도하게 증식됨.
3. 그렇다고 유저가 매번 `/log`와 같이 엄격한 명령어를 입력하도록 강제하는 것은 왓슨이 지향하는 '개인 AI 비서(Butler)'의 자연스러운 유저 경험을 저해함.

---

## 2. 의사결정 (Decision)

### 2.1. 대화(Chat)와 라이프로그(LifeLog)의 명확한 분리
* **단순 잡담/질의응답**: 일상 대화(날씨, 인사, 정보 질문 등)는 세션 대화 히스토리 DB에만 저장하며, 마크다운 파일 작성 및 Git 커밋을 일체 수행하지 않는다.
* **라이프로그 가치 발견 (Proactive Butler Suggestion)**: 사용자가 운동, 미팅, 프로젝트 성과, 감정, 식사, 생각 등 삶의 의미 있는 일과를 언급하면 비서가 대화로 공감함과 동시에 **"오늘 자 라이프로그에 기록해 둘까요?"**라고 능동적으로 제안한다. 해당 제안 내용은 세션 상태(`pending_log`)에 임시 보관된다.

### 2.2. 옵션 A: 확정 시 1기록 1커밋 (Immediate Commit on Confirmation)
* 사용자가 제안에 대해 승인("응", "좋아", "기록해줘")하거나 명시적으로 직접 기록을 요청(`/log`)한 경우에만:
  1. 당일 마크다운 라이프로그 파일(`lifelogs/YYYY/MM/YYYY-MM-DD.md`)의 적절한 섹션(Workout, Daily Notes 등)에 정제된 형태로 기록한다.
  2. 마크다운 파일 반영 즉시 **`git commit` & `git push`를 집행**한다. (1기록 1커밋 원칙)
  3. 세션 내 임시 보관된 `pending_log`를 초기화하고 유저에게 기록 완료 및 커밋 결과를 보고한다.
* **다중 세션(Multi-Session) 정합성 보장**: 모바일 텔레그램과 웹 대시보드 등 여러 세션을 동시 사용할 때 세션 간 기록 유실이나 충돌을 방지하기 위해, 의미 있는 기록이 확정될 때마다 중앙 저장소(GitHub)에 즉각 안전하게 영속화한다.

---

## 3. 결과 및 영향 (Consequences)

### Positive (긍정적 영향)
* **진정한 비서 UX**: 유저가 수동 명령어를 칠 필요 없이, 비서가 알아서 캐치하여 제안하고 자연스럽게 승인/기록.
* **Git 히스토리 청결성**: 의미 있는 실제 라이프로그 항목에 대해서만 유의미한 커밋 생성.
* **다중 세션 데이터 무결성**: 텔레그램/웹 등 여러 채널에서 발생한 기록이 지체 없이 당일 마크다운 파일에 즉시 동기화됨.

### Negative / Risk (주의사항)
* 사용자의 승인/거절 의도 및 일과 가치 감지를 위한 정밀한 패턴 및 언어 이해 로직 필요.
