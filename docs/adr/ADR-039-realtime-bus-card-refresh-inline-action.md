# ADR-039: 실시간 버스 도착 정보 원터치 인라인 갱신 및 웹/텔레그램 동시 지원

## 1. 배경 (Context)
- ADR-037 및 ADR-038을 통해 서울시 TOPIS 및 국토교통부 TAGO 버스 도착 정보 API를 연동하고 정류소 번호 자동 역조회를 구현하였다.
- 그러나 출근 전 아침 브리핑을 읽거나 집을 나설 준비를 하는 동안 버스 도착 잔여 시간(예: "4분 후 도착")이 계속 변화하지만, 최신 정보를 확인하려면 다시 `/bus`를 타이핑하거나 새로운 질의를 보내야 했다.
- 이로 인해 채팅창에 중복된 버스 카드 메시지가 쌓이고 불필요한 LLM 추론 비용과 왕복 지연시간이 발생하였다.
- 사용자는 텔레그램 메신저뿐만 아니라 웹 대시보드 콘솔에서도 기존 말풍선/메시지를 그 자리에서 즉시 새로고침할 수 있는 원터치 인라인 갱신(`[🔄 버스 도착 갱신]`) 인터랙션을 요구하였다.

## 2. 의사결정 (Decision)
1. **강제 갱신 매개변수 지원 및 초 단위 타임스탬프 (`BusService.get_arrival_info`, `CommuteConfigService`)**:
   - `BusService.get_arrival_info(..., force_refresh: bool = False)` 매개변수를 추가하여, 사용자가 새로고침을 요청할 경우 45초 인메모리 캐시를 우회하고 최신 실시간 도착 정보를 강제 조회하도록 구현한다.
   - 단독 버스 카드(`get_standalone_bus_card`)의 조회 일시에 초 단위 타임스탬프(`%H:%M:%S KST`)를 적용하여 매 갱신 시각을 명확히 시각화한다.
2. **REST 기반 실시간 버스 카드 갱신 API 신설 (`settings_router.py`)**:
   - `GET/POST /api/settings/commute/bus-card` 엔드포인트를 제공하여 웹 대시보드와 클라이언트가 최신 마크다운 카드, 출근 버스 요약 행(`transit_line`), 갱신 시각(`updated_time`)을 즉시 반환받을 수 있도록 한다.
3. **텔레그램 인라인 키보드 및 인플레이스 메시지 수정 (`TelegramService`)**:
   - `edit_message_text(chat_id, message_id, text, reply_markup)` 메서드를 구현하고, 버스 카드 및 아침 브리핑 하단에 `[🔄 실시간 버스 갱신]` (`callback_data="action_refresh_bus"`) 버튼을 부착한다.
   - 버튼 터치 시 신규 메시지를 발송하지 않고 `editMessageText`를 통해 기존 메시지의 텍스트와 키보드를 인플레이스(In-place)로 즉시 갱신하며, 0.1초 햅틱 토스트 응답을 제공한다.
4. **웹 대시보드 콘솔 인라인 액션 바 및 숏컷 칩 (`main.js`, `style.css`, `index.html`)**:
   - 챗봇 말풍선 중 버스 도착 정보가 포함된 어시스턴트 메시지 하단에 `.bus-refresh-bar` 및 `[🔄 버스 도착 갱신]` 버튼을 자동 렌더링한다.
   - 클릭 시 비동기 API 요청을 통해 기존 말풍선 내 도착 현황 텍스트를 인라인으로 교체하고, `[✅ 08:45:12 갱신됨]` 배지 피드백을 표시한다.
   - 퀵 바에 `[🚍 버스 도착]` (`data-cmd="/bus"`) 원클릭 칩을 신설하여 언제든 최신 버스 카드를 즉시 호출할 수 있도록 한다.

## 3. 결과 및 효과 (Consequences)
- **채팅방 청결 및 제로-중복 (Zero-Duplicate)**: 버스 잔여 시간을 확인할 때마다 새 메시지가 늘어나는 대신, 단 하나의 카드에서 시간 카운트다운을 지속적으로 갱신하여 쾌적한 UX를 달성하였다.
- **텔레그램-웹 대시보드 경험 일관성**: 모바일 텔레그램의 `editMessageText`와 PC/모바일 웹 콘솔의 In-place DOM 갱신이 동일한 백엔드 API를 공유하여 완벽한 크로스 플랫폼 일관성을 제공한다.
- **초고속 응답 & LLM 토큰 절약**: 실시간 갱신 시 LLM 추론 루프를 거치지 않고 전용 백엔드 엔드포인트를 통해 0.1초 내 버스 API와 직접 통신하므로 서버 리소스와 응답 속도를 극대화하였다.
