# ADR-009: GTD 저장소 원격 동기화(Git Pull) 및 온디맨드 최신화 파이프라인

* **상태 (Status)**: 승인됨 (Accepted)
* **날짜 (Date)**: 2026-09-08
* **작성자 (Author)**: Watson Core Team & User

---

## 1. 맥락 (Context)
사용자가 텔레그램을 통해 **"gtd 레포 최신화하고 다시 알려줘"** 또는 **"레포 최신화"**를 요청했을 때, Watson이 GTD 저장소의 원격 변경사항을 `git pull`하지 않고 기존 로컬 파일만 다시 조회하여 이전과 동일한 내용을 회신하는 문제가 발생했다.

### 원인 분석
1. **Git Pull / 동기화 기능 부재**:
   * 기존 `GitService`는 파일 수정 후 커밋/푸시(`sync_and_commit_push`)하는 로직만 갖추고 있었으며, 원격의 최신 변경사항을 가져오는 독립적인 `pull()` 메서드가 없었다.
2. **동기화 인텐트(`repo_sync`) 및 복합 파이프라인 부재**:
   * 사용자의 자연어 요청("최신화", "동기화", "pull", "최신화하고 알려줘")을 인식하는 인텐트 분류가 없었으며, 브리핑 전 원격 동기화를 선행 수행하는 파이프라인이 구현되지 않았다.
3. **다중 환경 작업 분산**:
   * 사용자는 모바일 Obsidian, 웹 GitHub, 타 PC 등 다양한 환경에서 GTD 저장소(`glshlee/life_log`)를 직접 수정할 수 있으므로, 왓슨이 로컬 파일만 신뢰할 경우 최신 할 일 목록과의 불일치가 지속 발생한다.

---

## 2. 의사결정 (Decision)

### 2.1. `GitService.pull()` 안전 동기화 메서드 구현
* 연결된 저장소의 원격 변경사항을 가져오는 `pull(autostash=True)` 로직 구현:
  ```python
  repo.git.pull(remote_name, branch, rebase=True, autostash=True)
  ```
* 로컬에 미커밋된 변경사항이 존재하더라도 `--autostash`를 통해 안전하게 임시 보관 후 원격 변경사항과 rebase 병합하여 데이터 유실 및 충돌을 방지한다.

### 2.2. 동기화 인텐트 분류 (`repo_sync`) 추가
* `LLMProvider`에 "최신화", "동기화", "pull", "sync", "가져와" 등의 키워드를 감지하는 `repo_sync` 인텐트 추가.
* 사용자가 "최신화하고 알려줘/정리해줘"와 같이 동기화와 브리핑을 동시에 요청한 경우(`sync_and_brief`), 먼저 원격 pull을 수행한 뒤 최신 마크다운 기반의 GTD 브리핑을 결합하여 응답한다.
* 단순 "레포 최신화", "/sync" 요청 시에는 pull 성공 여부와 동기화된 상태를 안내한다.

### 2.3. `task_briefing` 시 자동 사전 동기화 (Auto-Pull on Briefing)
* 사용자가 "오늘 해야 할 일 정리해줘"를 요청할 때도 원격 저장소가 설정되어 있다면 사전에 백그라운드로 안전하게 `git pull`을 시도하여 항상 실시간 최신 GTD 상태를 브리핑한다.

---

## 3. 결과 및 영향 (Consequences)

### Positive (긍정적 영향)
* **언제나 최신 GTD 상태 보장**: 모바일이나 다른 기기에서 GitHub에 푸시한 할 일/일정이 왓슨 브리핑에 즉시 반영됨.
* **직관적인 동기화 명령 지원**: "gtd 레포 최신화하고 다시 알려줘", "레포 최신화", `/sync` 명령으로 원격 상태를 언제든 수동 갱신 가능.
* **안전한 작업 트리 보존**: `autostash` 옵션을 통해 로컬 편집본 충돌 없이 무중단으로 원격 변경분 적용.
