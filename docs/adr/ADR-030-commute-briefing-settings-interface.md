# ADR-030: 출근길 맞춤형 브리핑 설정 인터페이스 및 동적 연동 체계 (Commute & Weather Briefing Settings Interface)

## 1. Context (배경 및 문제점)
사용자 피드백:
- *"와이프의 개발 요구사항이 있어. gtd에 우리지역 날씨, 미세먼지, 출근길 버스 정보를 알려달래. 어때보여?"* ➔ *"진행해"* ➔ *"위 정보는 입력받는 인터페이스를 만들어"*

1. **가족 맞춤형 생활 밀착형 정보에 대한 동적 입력 인터페이스 부재**:
   - 사용자와 배우자의 일상 동선(거주 지역, 대기 측정소, 자주 탑승하는 정류소명/ID, 버스 노선 번호)은 가변적이며, 이를 하드코딩하거나 복잡한 터미널 환경변수(`.env`)로만 관리하기에는 접근성이 현저히 떨어짐.
   - 웹 대시보드 및 텔레그램 환경에서 직관적으로 거주 지역, 출근 버스, 발송 희망 시각(KST), 공공데이터 API 키를 입력·수정하고 즉시 영속화할 수 있는 전용 UI와 API가 필요함.
2. **공공데이터포털(data.go.kr) API 키 미보유/발급 대기 시의 시스템 복원력(Resilience)**:
   - 기상청 단기예보, 에어코리아 대기오염정보, 국토교통부(TAGO) 버스 도착정보 API 키가 없거나 외부 API 서버 점검 중일 때도 전체 GTD 브리핑이 중단되지 않고, 스마트 시뮬레이션(Mock) 폴백으로 안전하게 동작해야 함.
3. **실시간 설정 검증 및 미리보기(Preview) 수단 필요**:
   - 저장 전 또는 설정 후, 내가 입력한 동네와 버스 정보가 실제 아침 브리핑 카드에서 어떻게 시각화되는지 1초 만에 확인하고 테스트할 수 있는 실시간 프리뷰 인터페이스가 필수적임.

---

## 2. Decision (결정 사항)

### 2.1 출근길 브리핑 설정 전용 영속화 서비스 (`CommuteConfigService`) 구축
- 설정 파일: `config/commute_config.json` (기본 템플릿 `config/commute_config.json.example` 제공)
- 스키마 정의:
  ```json
  {
    "enabled": true,
    "send_time": "07:30",
    "weekdays_only": true,
    "location_name": "서울 강남구 역삼동",
    "grid_x": 61,
    "grid_y": 125,
    "air_station_name": "강남구",
    "bus_stop_name": "역삼역",
    "bus_stop_id": "23284",
    "bus_route_name": "146",
    "bus_route_id": "",
    "city_code": "11",
    "public_data_api_key": "",
    "use_mock_fallback": true,
    "updated_at": "..."
  }
  ```
- **보안 마스킹 보존**: `get_masked_config()`를 통해 API 키는 앞뒤 일부만 남기고 `****` 마스킹 처리하여 UI/API로 노출하고, 마스킹된 상태로 재저장 시 기존 실제 인증키를 안전하게 보존.

### 2.2 설정 전용 RESTful API 엔드포인트 (`app/routers/settings_router.py`)
- `GET /api/settings/commute`: 현재 설정 조회 (API 키 마스킹 포함)
- `POST /api/settings/commute`: 설정 유효성 검증(HH:MM 시간 포맷 등) 후 디스크 영속화
- `POST /api/settings/commute/preview`: 입력된 임시 설정 또는 저장된 설정을 바탕으로 실시간 모닝 브리핑 카드 마크다운 렌더링 반환

### 2.3 웹 대시보드 인터페이스 (`index.html`, `dev.html`, `main.js`, `style.css`)
- **상단 헤더 배지**: `#commute-settings-badge` (`[🚌 출근: 07:30]`) 배치 및 원클릭 모달 호출.
- **빠른 실행 칩 바**: `[🚌 출근길 설정]` 칩 버튼을 배치하여 타이핑 없이 1초 접근 지원.
- **인터랙티브 모달 (`#commute-modal`)**:
  - 📍 **1. 우리 동네 (날씨 & 대기질)**: 지역명, 기상 격자 X/Y 좌표, 에어코리아 측정소명
  - 🚌 **2. 출근길 버스**: 탑승 정류소명, 정류소 ID(ARS-ID), 버스 노선 번호, 시/도 도시코드
  - ⏰ **3. 발송 스케줄**: 모닝 알림 활성화 스위치, 발송 희망 시각(`07:30`), 평일(월~금) 전용 체크
  - 🔑 **4. 공공데이터 연동**: 일반 인증키 입력란, 스마트 시뮬레이션 폴백 토글
  - **실시간 미리보기 기능**: `[🔍 실시간 미리보기]` 클릭 시 모달 내 렌더링 박스(`#commute-preview-section`)에 날씨/미세먼지/버스 카드가 즉시 시뮬레이션 표시됨.

### 2.4 대화형 명령어 및 텔레그램 연동 (`SupervisorService`, `llm_provider.py`)
- `/commute`: 현재 출근길 브리핑 설정 현황 및 웹 설정 모달 안내 출력.
- `/commute test` 또는 `/commute preview`: 현재 설정 기반 실시간 출근 브리핑 카드 즉시 출력.
- "출근길", "우리 동네 날씨", "출근 버스", "버스 언제 와" 등 자연어 질의도 `commute_inspect` 인텐트로 자동 라우팅.

## 3. Consequences (영향 및 효과)
1. **와이프/가족 맞춤형 생활 밀착형 UX 완비**: 코드 수정이나 서버 재시작 없이 브라우저나 채팅창에서 언제든 거주지, 버스 정류소, 노선 번호, 알림 시각을 변경하고 즉시 적용 가능.
2. **무중단 시뮬레이션 모드 지원**: 공공데이터 API 키 발급 전이거나 외부 서버 장애 시에도 시스템이 중단되지 않고 합리적 시뮬레이션 데이터로 안전하게 작동.
3. **시각적 사전 검증(Preview) 제공**: 실제 아침 푸시가 발송되기 전에 어떤 카드 형태로 브리핑되는지 눈으로 직접 확인 가능하여 사용자 신뢰도 극대화.
