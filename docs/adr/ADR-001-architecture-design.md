# ADR-001: 24/7 서버 가동 AI 에이전트 기반 GitHub 라이프로그 관리 시스템 아키텍처 선정

* **상태 (Status)**: 승인됨 (Accepted)
* **날짜 (Date)**: 2026-08-03
* **작성자 (Author)**: Watson Core Team

---

## 1. 맥락 (Context)
기존 사용자는 개인 노트북/PC에서 AI 에이전트(AGY 등)를 실행하여 GitHub 기반 마크다운 라이프로그를 관리하고 있었으나, 노트북이 꺼지면 기록 및 깃 푸시(Git Push)가 불가능하다는 물리적 한계가 존재했다.
이를 해결하기 위해 24시간 가동되는 개인 서버를 확보하였으며, 서버 환경에서 언제 어디서나 접속해 AI 에이전트에게 내 삶의 기록을 전달하고, AI가 마크다운 정제 후 GitHub에 자동 커밋/푸시하는 시스템 구축이 필요해졌다.

---

## 2. 의사결정 (Decision)

### 2.1. 백엔드 및 에이전트 코어
* **언어 및 프레임워크**: Python 3.10+ 및 FastAPI
* **이유**: 경량화된 비동기(async) HTTP 서버를 제공하고, AI LLM API SDK 및 Git 작업과의 연동성이 뛰어남.

### 2.2. 사용자 인터페이스 (Multi-Channel Interface)
1. **텔레그램 봇 (Telegram Bot)**:
   * **목적**: 모바일에서의 즉시성 확보.
   * **이유**: 별도 앱 개발 없이 모바일에서 음성/텍스트/이미지를 가장 쉽고 빠르게 에이전트로 전송할 수 있음.
2. **웹 대시보드 (Watson Web UI)**:
   * **목적**: PC/모바일 웹 브라우저에서의 시각화 및 편집.
   * **이유**: 작성된 마크다운 라이프 로그를 캘린더 뷰로 한눈에 보고, AI 대화창 및 수동 편집기를 제공하기 위함.

### 2.3. Git 자동화 파이프라인
* **방식**: Python 백그라운드 워커 기반 Git 연동 (GitPython 또는 CLI shell wrapper)
* **흐름**: 메시지 수신 ➔ AI 파싱 & MD 템플릿 작성 ➔ `git pull --rebase` ➔ `git add/commit` ➔ `git push` ➔ 결과 통보

---

## 3. 결과 및 영향 (Consequences)

### Positive (긍정적 영향)
* **24/7 가용성**: 노트북 연결 상태와 무관하게 365일 어디서나 텔레그램이나 웹으로 라이프로그 입력 가능.
* **자동화**: 깃 커밋/푸시 과정이 완전히 자동화되어 수동 명령어 실행 불필요.
* **유연한 인터페이스**: 이동 중에는 텔레그램, 책상 앞에서는 웹 대시보드로 유연하게 이용 가능.

### Negative / Risk (주의사항 및 위험)
* **Git 충돌 위험**: 수동으로 깃허브 웹에서 직접 수정했을 때 서버 로컬과의 충돌 가능성 ➔ `git pull --rebase` 자동화 처리로 회피.
* **보안**: Telegram Bot User ID 화이트리스트 검증 및 API Key의 `.env` 엄격 관리 필요.
