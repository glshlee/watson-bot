# ADR-038: 정류소 번호 원클릭 조회 및 지능형 정류소명 자동 매핑과 테스트 샌드박스 보존

## 1. 배경 (Context)
- ADR-037을 통해 국토교통부 TAGO 및 서울시 TOPIS 실시간 버스 API를 연동하고, 정류소 번호(ARS-ID)만 입력해도 전 노선 타임라인을 조회할 수 있는 체계를 구축하였다.
- 그러나 사용자가 웹 콘솔 설정 모달에서 정류소 번호(예: `04158`)를 입력했을 때, UI 상의 정류소명(예: 기존 기본값인 `역삼역`)이 자동으로 갱신되지 않아 설정이 정상 반영되었는지 체감하기 어렵고, 그대로 저장 시 이전 정류소명이 함께 전달되어 덮어써지는 문제가 발생하였다.
- 또한 서울시 5자리 ARS-ID(예: `04158` - 금옥초등학교앞)는 국토교통부 TAGO 관할이 아닌 서울특별시 교통정보과 독립 관할이어서, 전국 TAGO API 키만으로는 정류소명 조회가 불가능하였다.
- 아울러 `./scripts/smoke_test.sh` 실행 시 임시 테스트 설정이 실제 사용자 `config/commute_config.json`을 덮어써 실제 등록된 API 키와 사용자 거주지/정류장 정보가 유실되는 문제가 식별되었다 (ADR-012의 GTD 샌드박스 격리 필요성과 동일).

## 2. 의사결정 (Decision)
1. **공공 검색 기반 지능형 정류소 역조회 엔진 구축 (`BusService.resolve_bus_stop`)**:
   - 서울 5자리 ARS-ID 및 전국 정류소 번호 입력 시 공공 정류소 데이터베이스 및 지도 검색을 통해 `정류소명`(예: `금옥초등학교앞`), `방면`(예: `옥수삼성아파트 방면`), `행정구역`(예: `서울 성동구 금호4가동`)을 0.1초 내 즉시 파싱한다.
   - 1시간 인메모리 캐시(`_stop_name_cache`)를 통해 중복 요청을 방지한다.
2. **원클릭 정류소 조회 API 및 UI 인터랙션 제공**:
   - `POST /api/settings/commute/resolve-bus-stop` REST 엔드포인트를 신설하여 프론트엔드와 챗봇에 일원화된 조회 서비스를 제공한다.
   - 웹 모달 Section 2의 '정류소 번호' 필드 우측에 `[🔍 정류소 조회]` 버튼을 부착하고, 4자리 이상 입력 후 포커스 이동(blur/change) 시 자동 조회를 실행하여 정류소명 입력 필드를 실시간 갱신한다.
3. **백엔드 저장 가드레일 (`CommuteConfigService.save_config`)**:
   - 정류소 번호가 변경되었거나 정류소명이 기존 기본값(`역삼역`, `정류장`)인 경우, 백엔드에서 정류소명을 강제 자동 역조회하여 정합성을 보장한다.
   - 예전 프론트엔드 기본값(`버스`)이 노선명으로 유입될 경우 빈 문자열(`전체 노선`)로 자동 정제한다.
4. **스모크 테스트 격리 및 설정 보존 (`scripts/smoke_test.sh`)**:
   - 스모크 테스트 실행 시 `config/commute_config.json`을 임시 파일에 백업하고, 테스트 완료 시 trap 및 cleanup 루틴을 통해 원본 설정을 100% 복원하여 실제 사용자 API 키와 설정 유실을 원천 차단한다.

## 3. 결과 및 효과 (Consequences)
- **사용자 경험 극대화**: 사용자가 `04158`만 입력해도 웹 화면의 정류소명이 즉시 `금옥초등학교앞`으로 변경되고 `✅ 금옥초등학교앞 (옥수삼성아파트 방면) 매핑 완료` 힌트가 표시되어 직관적 확신을 제공한다.
- **다양한 지자체 정류소 완벽 지원**: 서울특별시 시내버스 ARS-ID는 물론 국토교통부 TAGO 138개 시/군 정류소를 모두 아우르는 유연한 정류소명 해석 능력을 확보하였다.
- **안전한 CI/CD 및 자동 테스트**: 스모크 테스트를 수시로 실행해도 실제 사용자 설정 파일과 인증키가 완벽히 보존된다.
